# AI Capper: правила разработки

Веб-приложение для аналитики теннисных ставок: React + TypeScript на фронтенде, FastAPI и PostgreSQL на бэкенде, анализ через Claude API. Что и зачем делаем — в [docs/PLAN.md](docs/PLAN.md). Раздел 0 плана («Решения владельца») главнее остального текста.

## Обязательные правила

Эти правила проверяются автоматически (хуки `.githooks/` и CI). Нарушать их нельзя.

1. **Автор — только владелец проекта.** Автор и коммитер всех коммитов: `Roman Burov <romanburov89@gmail.com>`.
2. **Claude нигде не указывается как автор или соавтор:** ни в коммитах, ни в описаниях pull request, ни в комментариях кода, ни в документах. Не добавлять строки `Co-Authored-By: Claude ...`, `Claude-Session: ...`, «Generated with Claude Code» и подобные. Упоминать Claude API как часть продукта (модель, которая делает анализ) можно.
3. **Не использовать букву «е с двумя точками»** (строчную U+0451 и заглавную U+0401), всегда писать «е». Правило касается кода, комментариев, текстов интерфейса, файлов переводов, документов и сообщений коммитов. Если код должен обрабатывать эту букву во вводе пользователя (например, при поиске по именам), пишите ее кодом: `\u0451`.
4. Хуки не обходить (`--no-verify` не использовать). Если хук сработал — исправить причину.

Настройка новой копии репозитория, один раз:

```bash
git config user.name "Roman Burov"
git config user.email "romanburov89@gmail.com"
git config commit.gpgsign false        # не подписывать коммиты чужим ключом
git config core.hooksPath .githooks    # включить проверки правил 1–3
```

Проверить весь репозиторий: `bash scripts/check-rules.sh`.

## Главный принцип: числа считает код, контекст дает Claude

- Вероятности базовой модели, банк, суммы ставок, ROI, CLV, Brier, лимиты и стоимость считает код (`backend/app/ml`, `backend/app/services`).
- Claude разбирает текст, собирает новости и дает поправку к вероятности с объяснением. Ответы Claude приходят по схеме (structured outputs) и проверяются кодом. Claude не пишет в базу напрямую.
- Каждый вызов Claude записывает токены и стоимость (`agent_runs`) и проверяет лимиты участника до вызова (решения Р9, Р13).
- Модели, effort и лимиты — в настройках, а не в коде маршрутов. Промпты — в `backend/app/prompts/*.md` с номером версии; опубликованную версию не правим, а создаем следующую.

## Backend (Python)

- Python 3.12+, FastAPI, Pydantic v2, SQLAlchemy 2 (async), Alembic, arq.
- Слои: `api` — только HTTP (разбор запроса, права, вызов сервиса, ответ); `services` — бизнес-логика; `db` — модели и запросы. Маршрут не обращается к базе мимо сервиса.
- Типы везде, `mypy` в строгом режиме. Стиль и импорты — `ruff`, длина строки 100.
- Идентификаторы на английском (`snake_case` для функций и переменных, `PascalCase` для классов). Комментарии и docstring — на русском, коротко и по делу: зачем, а не что.
- Деньги — `Decimal`, в базе `NUMERIC(12, 2)`, у каждой суммы есть валюта. Валюта программы одна (₽, $ или €) и задается в настройках администратора (Р17). Расходы на Claude всегда в долларах. Кэфы — `NUMERIC(6, 3)`, вероятности — `float` от 0 до 1.
- Время в базе — UTC (`timestamptz`), показывается в часовом поясе пользователя.
- Схема базы меняется только миграцией Alembic. Примененную миграцию не правим.
- Права проверяются на каждом маршруте. Ставки, банк и стратегию участника видит он сам и администратор (только просмотр, каждый просмотр — в журнал, Р27); другие участники — нет. Пароли, коды 2FA и ключи Claude участника не видит никто. `/admin/*` — только роль `admin`.
- Тексты для пользователя (ошибки, уведомления) — в `backend/app/locales/ru.json`, в коде — ключ.
- Тесты — `pytest`. На каждый новый маршрут — тест прав: участник не видит чужое, не-администратор не попадает в `/admin/*`.

## Frontend (TypeScript)

- React + TypeScript в строгом режиме, Vite. Компоненты-функции и хуки.
- Все тексты интерфейса — только в `frontend/src/i18n/locales/ru.json`, в коде — `t('раздел.ключ')`. Русские строки прямо в JSX не пишем: английский добавляется файлом `en.json` без правки кода (Р18).
- Данные с сервера — через клиент `src/api` и TanStack Query. Типы API генерируются из OpenAPI бэкенда, руками не дублируются.
- Деньги и даты форматируются только через `src/lib/format.ts`.
- Вид — как в согласованном макете `mockup/`. Цвета и размеры — токены из `src/styles/tokens.css`, без «магических» цветов. Светлая и темная темы.
- Мобильная версия обязательна: проверять на ширине 375 px, зоны нажатия не меньше 40 px.
- Один компонент выпадающего списка на все приложение (как в макете), без системных `select` и `datalist`.
- Файлы компонентов — `PascalCase.tsx`, хуки — `useSomething`, остальное — `camelCase`.

## Безопасность

- Секреты только в `.env` на сервере, в git — никогда. Ключи Claude (администратора и участников) хранятся в базе в зашифрованном виде, в браузер и в логи не попадают.
- Пароли — Argon2id, вход с 2FA, регистрация только по приглашению (Р4–Р6).
- Персональные данные участников из ЕС — по GDPR: сервер в Финляндии (Р19), экспорт и удаление данных по запросу (PLAN.md, раздел 7).

## Коммиты

- Сообщение на русском. Первая строка — что изменилось, в формате «Раздел: суть», например «Backend: вход по коду приглашения» или «Макет: кабинет администратора». Подробности — после пустой строки.
- Один коммит — одно логическое изменение. Перед коммитом проходят проверки:

```bash
bash scripts/check-rules.sh
cd backend && ruff check . && ruff format --check . && mypy && pytest
cd frontend && npm run build
```

- Ветка в репозитории одна — `master`: коммиты сразу в нее, другие ветки не создаем. Перед отправкой — проверки выше; после отправки CI на `master` должен быть зеленым.
