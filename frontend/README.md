# Frontend

Интерфейс AI Capper: React 19 + TypeScript 7 + Vite 8. Экраны и поведение повторяют согласованный макет ([mockup/](../mockup/README.md)). Правила написания кода — в [CLAUDE.md](../CLAUDE.md).

## Запуск для разработки

Нужен Node.js 22.

```bash
cd frontend
npm install
npm run dev          # http://localhost:5173, запросы /api уходят на backend (порт 8000)
```

Без запущенного backend оболочка покажет ошибку связи: `GET /api/me` — первый запрос приложения.

## Типы API

Типы запросов и ответов генерируются из OpenAPI бэкенда и руками не дублируются:

```bash
npm run gen:api      # backend → openapi.json → src/api/schema.d.ts
```

Скрипт `scripts/gen-api.mjs` запускает `python -m app.openapi_export` из `../backend` (Python из `backend/.venv`, а если его нет — `python3`; сервер и база не нужны), затем `openapi-typescript`. Генератор работает только с TypeScript 5, а приложение собирается TypeScript 7, поэтому он стоит отдельным пакетом в `scripts/openapi-ts/` со своим `package-lock.json` и при первом запуске ставится сам. Оба файла (`openapi.json`, `src/api/schema.d.ts`) коммитятся; после изменения API бэкенда — перегенерировать.

## Проверки

```bash
npm run typecheck    # tsc: приложение и e2e
npm run test         # vitest: форматирование, компоненты, графики, клиент API, маршруты, экраны
npm run build        # tsc + vite build → dist/ и отчет размеров; больше бюджета JS — ошибка
npm run e2e          # Playwright: смоук оболочки и сквозные сценарии на настоящем API
```

### Тесты экранов (vitest)

Экран рендерит `renderPage` из `src/test/renderPage.tsx`: роутер в памяти, QueryClient приложения без повторов (`createTestQueryClient`: настройки приложения — кэш 30 с, мутации без повторов — плюс `retry: false`), тема, всплывающие сообщения и подмена API.

```tsx
const { router, calls, user } = renderPage(<BetsPage />, {
  path: '/bets',                                   // шаблон адреса, как в router.tsx
  url: '/bets?status=open',                        // откуда начинается тест (по умолчанию path)
  me: ME_MEMBER,                                   // пользователь в кэше; null — без него
  api: { 'GET /api/bets': () => json(betsPage()) },// поверх общих ответов (CSRF, /api/me, валюта, колокольчик)
  stubs: { '/analysis/:id': 'Экран анализа' },     // куда экран уводит
  width: 375,                                      // телефон
});
```

Адрес с `?as=<id>` (или `viewMode: true`) открывает экран в режиме просмотра данных участника (Р27), как в оболочке: запросы идут с `as_user`, ключи кэша — под `['view', id]`, кнопки с `ro` неактивны (`src/features/view/`).

Фабрики ответов — `src/test/factories.ts` (`baseApi`, `dashboardApi`, `settingsOut`, `bankOut`, `aiBudget`…) и `features/<раздел>/testData.ts`: каждый вызов — новый объект, типы из OpenAPI. Графики проверяются числами: геометрия — чистые функции (`components/charts/geometry.ts`), значения — через подсказку, текст для читалки экрана и таблицу-двойник (в jsdom у элементов нет размеров, ширина графика задается пропом `width`).

### Сквозные тесты (Playwright)

Четыре проекта в `playwright.config.ts`:

- `shell` — смоук оболочки на 360, 375 и 1366 px в обеих темах, API подменяется в самих тестах (`e2e/shell.spec.ts`, ответы — `mockApi` из `e2e/fixtures.ts`: сам отвечает на то, что нужно любому экрану, как `baseApi`; ответы экрана — третьим аргументом, для главной — `dashboardApi()`, тот же набор, что в unit-фабриках; типы — из OpenAPI); там же — экран, файл которого пропал после выкладки (одна автоперезагрузка, потом «Экран не загрузился» и «Обновить страницу») и долгий переход на экран (индикатор);
- `mobile-360` — самый узкий телефон из PLAN.md (360 px): сценарии с меткой `@360` (`test('…', { tag: '@360' }, …)`) — раскладка экранов на телефоне, без повтора всех сценариев третий раз;
- `desktop` (1366 px) и `mobile` (375 px, сенсорный экран) — сценарии `e2e/flows/` на настоящем backend:
  1. администратор из терминала: первый вход, настройка 2FA, резервные коды, вход с кодом и резервным кодом;
  2. приглашение → регистрация → 2FA; у участника нет «Администрирования» ни в меню, ни по адресам `/admin/*`, API отвечает 403;
  3. код сброса от администратора → новый пароль на `/reset` → вход с 2FA, старый пароль не подходит;
  4. пять неверных паролей → экран «Вход временно закрыт» с отсчетом; с другого IP вход работает;
  5. участник завершает сеанс на другом устройстве — то уходит на вход с «Сеанс завершен»;
  6. блокировка закрывает открытый сеанс участника, после разблокировки вход работает;
  7. анализ: текст из двух матчей → разбор → запуск → ход по SSE → итог с экспрессом → «Сохранить ставку» с правкой кэфа → банк уменьшился (`analysis.spec.ts`);
  8. сбой шага Claude → «Перезапустить с этого шага» → итог, попытка 2 (`analysis-fail.spec.ts`); отмена анализа → «Продолжить с шага N» → «Изменить события» (`analysis-cancel.spec.ts`);
  9. телефон 375 px: панель запуска, вкладки карточки матча, без горизонтальной прокрутки (`analysis-mobile.spec.ts`);
  10. свой ключ Claude участника, просьба вернуть ключ администратора и разрешение с лимитом; замена ключа администратора с кодом 2FA, бюджет, порог и лимит участника (`keys.spec.ts`);
  11. приемка этапа 4: анализ → ставка → результат с закрывающими кэфами → главная за все время, итоги «Ставок» и «Аналитика» показывают одни и те же числа (и в ответах сервера, и на экранах) → «Исправить результат» → числа новые и снова одинаковые → исправить обратно → числа вернулись (`same-numbers.spec.ts`); «Игроки» → поиск → карточка → сегодняшний матч с Эло обоих → анализ (`player-analysis.spec.ts`); «Обзор» → «Расход ИИ» → смена валюты → участник с открытым приложением, переходя пунктами меню без перезагрузки, видит новую валюту и на экране, и в плашке «Банк» (`admin-settings-currency.spec.ts`, проект `exclusive`);
  12. все маршруты приложения на 375 и 360 px в обеих темах — без прокрутки вбок, с зонами нажатия от 40 px по всей странице (с шапкой, меню и нижними вкладками; у участника и администратора — еще и с открытым колокольчиком, у администратора — его виды «Обучения модели», и с окнами этапа 5: ставка с разбором ИИ, предложение правил суммы, предложение урока) и без ошибок консоли (`all-routes.spec.ts`);
  13. сквозной сценарий этапа 5 (`learning-loop.spec.ts`, проект `loop` — после `exclusive`): анализ → ставка → администратор загружает файл tennis-data → ставка рассчитана сама → уведомление → «Ставки» (авто · архив) → разбор ИИ пакетом на поддельном Claude (команда `cli postmortems`) → гипотеза → урок → проверка на истории (`learning_seed.py ready`) → быстрая проверка → «Включить в инструкции» → следующий анализ идет с версией инструкций с уроком (журнал вызовов и «ИИ и расходы») → «Вернуть» прежнюю версию; раскладка экранов с данными на 375 и 360 px. В конце `learning_seed.py postmortem-cleanup` убирает разборы, пакеты, урок и его версии — сценарий повторяется на одном стеке: `npx playwright test learning-loop --project=loop --no-deps`. 
  14. этап 6 (`pwa.spec.ts`): манифест, значки, service worker и кэш оболочки без ответов API; без сети — «Нет связи», связь вернулась — экран ушел сам, перезагрузка без сети — оболочка из кэша; push участника: «Включить push» → тестовый push дошел до поддельного сервиса (подпись VAPID, текст) → настройки push и тихие часы сохраняются → сообщение администратора с «Также push» дошло → «Отключить» → выход отзывает подписку.
  15. Р27 (`member-view.spec.ts`): администратор открывает «Администрирование → Сводка» → строку участника → его главную и «Ставки» глазами участника (адрес `?as=<id>`, плашка «Вы смотрите данные», кнопки изменения неактивны) → «Экспорт CSV» его ставок → «Банк и стратегия» без форм → «Вернуться к своим» → журнал показывает просмотры и выгрузку; участник выбора «Чьи данные смотреть» не видит, адрес с `?as=` чужого дает ошибку, сервер отвечает 403. Список адресов строится из `src/app/router.tsx` (`e2e/support/routes.ts`): новый маршрут, для которого там не сказано, какими адресами его открыть, роняет проверку.

Стек для них поднимает `scripts/e2e-stack.sh` (Playwright запускает его сам): временная база `capper_e2e_<порт>` с миграциями и 6 игроками с матчами (`backend/tests/analysis_helpers.py`), свой префикс ключей Redis, поддельный Claude API (`backend/tests/fake_claude.py`, порт API + 99) с фальшивым ключом администратора, uvicorn на порту 8000 (`CAPPER_ENV=test`), воркер arq без расписания (`CAPPER_WORKER_CRON=false`: ночная загрузка архивов не начнется посреди прогона), сборка фронтенда и `vite preview` на 4173 с прокси `/api`. Повтор оценки Claude выключен (`assessment_reuse_hours=0`): каждый анализ вызывает поддельный Claude. При остановке база и ключи удаляются. Нужны PostgreSQL и Redis, как для тестов backend (`capper:capper@localhost:5432`, `localhost:6379`), и зависимости backend (`backend/.venv` или `python3`).

```bash
npx playwright test                          # все: стек поднимется и остановится сам
npx playwright test --project=desktop        # только сценарии на 1366 px
bash ../scripts/e2e-stack.sh                 # стек в отдельном терминале: тесты его переиспользуют,
                                             # а в браузере можно войти как owner@e2e.test
                                             # (пароль — в начале скрипта)
E2E_API_PORT=8400 E2E_WEB_PORT=4400 npx playwright test   # если порты 8000 и 4173 заняты
```

Как устроены сценарии (`e2e/support/`):

- Администраторов создает команда терминала: `bash scripts/e2e-stack.sh cli create-admin --email ... --password-stdin`. Подготовка, которая не проверяется в сценарии (2FA администратора, участник по приглашению), идет через API.
- Коды 2FA тест считает сам по секрету с экрана настройки (`support/totp.ts`, RFC 6238 на `node:crypto`). Сервер не принимает шаг кода дважды, поэтому помощник помнит последний шаг и берет следующий, без ожидания 30 секунд.
- У каждого браузера свой IP-адрес: заголовок `X-Forwarded-For` проходит через `vite preview`, а API верит ему от `127.0.0.1` (`CAPPER_TRUSTED_PROXIES`). Так лимиты попыток входа у тестов не пересекаются, а сценарий 4 проверяет паузу честно: один IP закрыт, другой входит.
- Почта и имена у каждого теста свои, поэтому тесты идут параллельно и повторяются на уже запущенном стеке. Ответ API 5xx и необработанное исключение на странице валят тест, даже если сценарий прошел.
- Сбой шага Claude тест включает на поддельном сервере (`POST /_fake/fail`, `support/fakeClaude.ts`). Сбой действует на весь сервер, поэтому сценарии, которые запускают анализ, идут по очереди под общим замком (`withFakeClaude`), а после сценария сбои снимаются.
- Раскладка телефона — `e2e/support/layout.ts`: `expectNoHorizontalScroll` (страница не шире окна), `expectTapTargets` (зоны нажатия от 40 px; флажок меряется по подписи, ссылка внутри предложения не считается, зона, расширенная псевдоэлементом `::before`/`::after` с `position: absolute`, считается целиком) и `expectScreenLayout` для нового экрана (прокрутка, а до 960 px — и зоны нажатия в `#view`).
- `vite preview` отдает ту же CSP, что Caddy: `vite.config.ts` берет ее строкой из `deploy/Caddyfile`. Нарушение CSP (встроенный скрипт, стиль или ресурс `data:`, которые сайт не пустит) — ошибка в консоли, и тест падает; смоук `shell` сверяет заголовок с Caddyfile.

В CI это job `e2e` (`.github/workflows/ci.yml`): службы PostgreSQL и Redis, `npx playwright install --with-deps chromium`, `npx playwright test`; при падении — артефакт `playwright-report` (HTML-отчет, трассы, скриншоты и логи стека). Локально Chromium берется из `PLAYWRIGHT_BROWSERS_PATH`; версия `@playwright/test` закреплена под установленный браузер (1.56.1 — Chromium 1194). На своей машине: `npx playwright install chromium`. Отчет после падения: `npx playwright show-report` или `npx playwright show-trace test-results/<тест>/trace.zip`.

## PWA и push (этап 6)

Приложение ставится на телефон и компьютер как PWA и получает push (Р26, макет — `mockup/js/pwa.js`, решения В1–В9 в `mockup/README.md`).

- **Манифест, offline.html и sw.js собирает `npm run build`** (плагин `capperPwa` — `src/pwa/plugin.ts`, подключен в `vite.config.ts`; чистые функции — `src/pwa/build.ts`): тексты — из `src/i18n/locales/ru.json` (`app.*`, `pwa.offline.*`), цвета — из `src/styles/tokens.css`, в `sw.js` подставляются файлы оболочки из собранного `index.html` и версия — хэш **содержимого** всех файлов оболочки в `dist` (поменялся `theme-init.js` или значок под тем же именем — sw.js другой, браузер ставит новую версию). В режиме разработки отдается только манифест, service worker не регистрируется (`src/pwa/register.ts`).
- **Значки** — PNG в `public/icons/` (192, 512, maskable 512, `apple-touch-icon` 180, badge 96) из `mockup/icons/*.svg`: `npm run gen:icons` (Chromium из Playwright, без новых зависимостей). PNG коммитятся.
- **Service worker** (`src/pwa/sw.js`) кэширует только оболочку (index.html, `/assets/*`, значки, offline.html) и **никогда — ответы `/api`** (В7). Файлы `/assets/*` (хэш в имени) — из кэша, остальные файлы оболочки — сначала из сети, кэш — только без нее. Переход без сети — оболочка из кэша (приложение само покажет «Нет связи»), без нее — offline.html. Новая версия включается при следующем открытии. Обработчики `push` (значок, badge, `tag`, адрес в `data.url`) и `notificationclick` (фокус на вкладке приложения или новое окно).
- **«Нет связи»** (`src/app/offline/`): поверх приложения при событии `offline` (`OfflineGate`, приложение под ним `inert`, состояние экранов не теряется), на месте приложения, если `/api/me` не дошел до сервера (`RequireAuth`), и по адресу `/offline`. «Повторить» спрашивает `GET /api/health`; связь вернулась — экран уходит сам.
- **Push на этом устройстве** (`src/features/pwa/`): `platform.ts` — система и браузер по User-Agent, открыто ли с экрана «Домой»; `push.ts` — состояние браузера (`PushState`: не включен, включен, запрещено, iPhone без установки, нет поддержки браузера или ключей на сервере), подписка с ключом VAPID, хэш `endpoint` как `endpoint_hash` сервера («это устройство»); `api.ts` — запросы `/api/me/push-*` и хуки экрана; `revoke.ts` — отзыв push этого устройства при «Выключить» и при выходе из аккаунта; `install.ts` — `beforeinstallprompt` (слушатель ставится при старте, `main.tsx`) и кнопка «Установить».
- **Экраны**: кабинет → «Уведомления» (столбец «Push», «Каналы», «Устройства с push», «Тихие часы», «Как выглядит push»), «Профиль» → «Приложение на телефоне», окно установки (`app/layout/InstallModal.tsx`: пункт в боковой панели и в «Еще»), «Администрирование → Сообщение» («Также push», «Push включен у N из M», превью push), подпись внизу колокольчика.
- **Тесты**: vitest подменяет браузер (`src/test/pushBrowser.ts`: service worker, `PushManager`, `Notification`, User-Agent, `navigator.standalone`), `src/pwa/sw.test.ts` гоняет `sw.js` в подмененном окружении (кэш, сеть, push, нажатие). Сквозной `e2e/flows/pwa.spec.ts`: манифест, значки и регистрация service worker; `context.setOffline` → «Нет связи» → связь вернулась; push участника на поддельный сервис стека (`e2e/support/push.ts`: подписка `POST /_fake/push/subscription`, полученные push — `GET /_fake/push`, подпись VAPID и расшифрованный текст). Headless Chromium не выдает настоящую подписку и всегда отвечает `Notification.permission = 'denied'`, поэтому `PushManager.subscribe` и разрешение подменяются init-скриптом. В остальных сценариях service worker выключен (`serviceWorkers: 'block'` в `playwright.config.ts`), PWA-сценарий включает его своим устройствам.
- **Только на телефоне с HTTPS** проверяются: настоящая подписка у сервиса push браузера (FCM, Apple, Mozilla), показ уведомления системой и переход по нажатию, установка на экран «Домой» (окно Chrome, шаги Safari), заставка Android и цвет строки состояния. Push и установка работают только по HTTPS (или на `localhost`).

## Сборка: ленивые экраны и размер

Экран грузится отдельным файлом, когда его открывают (`src/app/lazyPage.ts`, `React.lazy` в `src/app/router.tsx`): вход, регистрация, сброс, «Новый анализ», «Анализ», личный кабинет, администрирование и все экраны этапа 4. Заглушки и «Такой страницы нет» — в общем файле, они крошечные. Пока файл грузится, на месте экрана — индикатор (с задержкой 0,3 с, на быстрой сети его не видно).

При переходе между экранами роутер меняет состояние в `startTransition`, и React держит на месте прежний экран, пока грузится новый; `useNavigation()` этого не видит (загрузка — на уровне компонента, а не маршрута). Поэтому оболочка следит за адресом роутера сама (`layout/usePendingNavigation.ts`): если переход длится дольше 0,3 с, в шапке и меню — уже новый экран, на месте прежнего — тот же индикатор, `main` с `aria-busy`. Прежний экран при этом скрыт, но не размонтирован. Быстрые переходы выглядят как раньше.

После выкладки новой версии старых файлов на сервере нет, и открытая со вчера вкладка не загрузит экран: `lazyPage` превращает любой отказ загрузки в `ChunkLoadError`, `RouteError` один раз сам перезагружает страницу. Если ошибка повторилась в течение минуты после этого, новая версия уже загружена — это сбой: «Экран не загрузился», «обновите через минуту, не поможет — сообщите администратору» и «Обновить страницу», без цикла (метка — `sessionStorage`). Текст «Вышла новая версия программы» — только без хранилища, когда страница сама не перезагружалась. Нет связи — «Нет связи с сервером», без автоперезагрузки.

Бюджет JS первого экрана — 250 КБ gzip (PLAN.md, «Целевые показатели»): столько браузер скачивает, открыв по ссылке любой экран. Его проверяет плагин `bundleBudget` в `vite.config.ts`: после `npm run build` он печатает размер каждого файла (gzip, zlib) с пометкой «сразу» или «по запросу», затем для каждого экрана — начальная загрузка + файл экрана с его статическими импортами + файл текстов экрана — и роняет сборку, если самый тяжелый экран больше бюджета, — в CI и в Docker-образе. То же в настоящем браузере проверяет `e2e/flows/profile-first-load.spec.ts` (все файлы JS, скачанные до затихания сети). Библиотеки основы (React, роутер, TanStack Query, i18next, openapi-fetch) — отдельным файлом `vendor-*.js`: они меняются реже кода, и после выкладки браузер берет их из кэша.

Тексты интерфейса — один файл на язык (`src/i18n/locales/ru.json`), но при сборке он делится (плагин `capperTexts` в `vite.config.ts`, состав — `src/i18n/sections.ts`): ядро (`CORE_TEXTS`) — в начальной загрузке: меню, шапка, колокольчик, ошибки, форматы и тексты общих компонентов; тексты экрана (`SCREEN_TEXTS`: свой раздел и нужные ветки чужих) — отдельным файлом `virtual:capper-texts/screen/<экран>`, его `lazyPage` грузит вместе с кодом экрана. Все тексты вне ядра (`rest-*.js`) — только запасной путь: если экрану не хватило ключа (например, ключ пришел с сервера), `missingKeyHandler` догружает их, и экран перерисовывается. Тест `src/i18n/i18n.test.ts` проходит по импортам каждого экрана и его ключам: новый ключ из чужого раздела — тест назовет файл и ключ, допишите ветку в `SCREEN_TEXTS`; ключ оболочки — в `CORE_TEXTS`.

## Графики

Свой SVG без библиотеки (`src/components/charts`, импорт — `from '../../components/charts'`), по образцу макета (`mockup/js/ui.js`) и правилам dataviz:

- `LineChart` — ряды, сетка, опорные линии пунктиром (банк на начало периода, ноль), заливка 10%, конечная метка, перекрестие; `ColumnChart` — столбцы от нуля вверх и вниз, не толще 24 px, скругление 4 px только на конце; `HBars` — полосы со знаком и 95% ДИ, значение всегда числом; `CalibrationChart` — прогноз против факта, размер точки — число событий, ДИ у точки; `Sparkline` — мини-график рядом с числом;
- `ChartWithTable` — легенда, «Показать таблицей» (таблица тех же данных — доступный двойник графика), пустое состояние и перезапрос (прежний график приглушен, без скелетона); `ChartLegend` — при двух и больше рядах;
- подсказка (`ChartTooltip`) — по наведению и с клавиатуры: фокус на графике, ← → Home End, Esc; то же значение читалке экрана; на телефоне — касанием и проведением пальцем;
- ширина — по контейнеру (`useChartWidth`, ResizeObserver), график перерисовывается под нее: подписи и линии не масштабируются; подписи оси X прореживаются без наложения (`pickAxisLabels`), ширина подписи считается по знакам шрифта (`textWidth`, замер Golos Text 11 px), поэтому подписи не уезжают за край; длинная конечная метка встает над точкой, если справа ей не хватает места;
- ось Y: деления круглые (`niceScale`, шаг 2, 5 или 10 × 10ⁿ, как в макете); если все значения целые (счетчики ставок и событий), деления тоже целые — «0, 1», а не «0, 0,5, 1» (проп `integer`); столбцы только с отрицательными значениями кончаются нулем сверху. Форматтер оси получает вторым аргументом шаг делений `{ step }` и должен различать соседние подписи: по умолчанию — число с точностью шага (`stepDigits`), для сумм — `formatMoneyCompact(v, currency, { step: axis?.step })` («990 тыс. ₽», «1 млн ₽», «1,01 млн ₽»); без второго аргумента — значение целиком (подсказка, конечная метка);
- калибровка: шкала по умолчанию — по данным (`calibrationDomain`: от круглой десятой ниже самого малого прогноза, доли и нижнего конца ДИ, не уже 60–100%), ничего не прижато к краю; при заданной шкале значения за ней помечены — полая точка, стрелка на конце ДИ, «за пределами шкалы» в подсказке и тексте для читалки;
- `HBars`: столбец значений общий для строк (CSS subgrid) и по ширине самого длинного значения — полосы в одной шкале, сумма с центами не вылезает за карточку;
- цвета — только токены (`var(--s1)`…`var(--s8)`, `CHART_COLORS`; покрытия — `--hard` и др. всегда с подписью: глина и трава при дейтеранопии сливаются), темная тема работает сама. Палитра проверена валидатором dataviz: светлая и темная темы проходят все проверки; у `--s3`, `--s4`, `--s5` в светлой теме контраст с фоном ниже 3:1 — с ними обязательны подписи или таблица;
- числа на графике считает сервер, график только рисует; подписи — через `t()`, числа — через `lib/format.ts` (форматтеры передаются пропами `yFormat`, `valueFormat`).

Правила, которые легко нарушить:

- Тексты — только `t('раздел.ключ')` из `src/i18n/locales/ru.json`, даже в `aria-label`. Каждый файл `locales/*.json` подключается сам (`src/i18n/index.ts`): английский — файл `en.json` без правки кода, язык берется из браузера, запасной — русский.
- Деньги, проценты, процентные пункты, кэфы и даты — только через `src/lib/format.ts` (п.п. — одна функция `formatPp`; `ppDelta` экрана анализа — обертка над ней с нулем «±0 п.п.»); даты показываются в часовом поясе пользователя (`users.tz`), а дата без времени («2026-10-03», ряд банка по дням) — как календарный день, в любом поясе. Пояс ставит клиент запросов, когда в кэше меняется профиль (`meQueryKey`), поэтому после входа достаточно `queryClient.setQueryData(meQueryKey, user)`.
- Возврат после входа — только через `safeNext(next)` из `src/app/paths.ts`: он отбрасывает чужие адреса.
- Выпадающий список — только `Dropdown`, без `select` и `datalist`.
- Новый экран — в `router.tsx` через `lazyPage`, а не прямым импортом: иначе он попадет в начальную загрузку.
- Цвета и размеры — токены из `src/styles/tokens.css`.
- Данные с сервера — `api` из `src/api/client.ts` + TanStack Query; ошибка — `ApiError`, показываем ее `message`.
